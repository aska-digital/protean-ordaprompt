Request routing that refuses to guess.

protean-ordaprompt is a Jev-style comparative classifier for OrdaPilot request routing. It compares every candidate label and session together in one batch, checks calibrated scores and margins, and returns a verdict.

The verdict has two parts: a band (automatic, escalate, or abstain) and a concrete decision (assign the topic, reuse the session, propose a new label, escalate, or open a new session). When it cannot prove the safe choice, it abstains and says why.

02How it works

One request in, one ranked comparison per surface, one closed decision out. The router asks the backend once per surface, not once per label, and scores every candidate side by side, sentinels included.

classify

Topic side

Compares all topic labels together, including the novel (new topic) and ambiguous sentinels. Returns a ranked list, a calibrated score, and the top-vs-second margin.

route-session

Session side

Adds a second comparison for session reuse, including the new_session sentinel. Session reuse is deliberately stricter than topic match: continuity is weighed against context cost and contamination risk.

RoutingDecision

Closed verdict

Two closed enums. band is automatic, fallback_escalate, or abstain_or_new_session. decision is topic_assign, session_reuse, novel_propose, escalate, or new_session. The escalate band hands the ranked candidates to the caller to ask. Abstention is a first-class outcome, never an error.

What abstains

Low confidence, a weak top-vs-second margin, genuine novelty, topic/session disagreement, or a contaminated session (project hash mismatch). If the topic and session winners disagree, the new_session sentinel wins and nothing routes.

What never happens

No guess on a sub-threshold score. No automatic routing without calibration. No free text in receipts, logs, or metadata, ever. Receipts carry hashes and structured scores only, and a privacy validator re-checks every outbound payload.

03Try the CLI

The plugin's only surface is the command line. Demo fixtures ship in eval/demo/ so you can run a classification in seconds.

git clone https://github.com/aska-digital/protean-ordaprompt
cd protean-ordaprompt
python3 -m ordaprompt_router.cli classify \
  --request eval/demo/request.json \
  --candidates eval/demo/candidates.json \
  --receipts-dir receipts/ --compact

Exit codes are part of the contract: 0 decision produced (receipt written when --receipts-dir is given) · 2 malformed request, nothing written · 3 receipt failed privacy/schema validation, nothing written. Any unexpected backend error becomes abstain, not a guess.

The routing layer ships with a deterministic, offline default adapter. A Jev/OpenJEV-style NLI backend can be attached later through the adapter contract. The plugin does not bundle a model and never starts a server. OpenRouter is an optional adapter reserved for provisional new-label proposals. It ships disabled by policy and carries hashes and labels only when explicitly enabled for one invocation.

04Fail-closed by design

The automatic band exists in the code but is structurally unreachable in this release. It unlocks only when expected calibration error drops to 0.05 or below on real feedback data.

The synthetic harness honestly reports topic ECE 0.1330 and session ECE 0.0635, above the gate. So the release ships with calibration_model_id = "none" and the automatic band locked. The unlock rule is simple: prove it on real data first.

ConditionBehavior
OpenRouter used while disabledDisabledByPolicy raised. Nothing sent, nothing written
Malformed request / candidate setexit code 2, schema error, nothing written
Sub-threshold score or marginabstain, never automatic
Topic and session winners disagreenew_session sentinel wins. No route
Contaminated session (project hash mismatch)session never promoted
Receipt fails privacy/schema validationexit code 3, receipt rejected, nothing written
Any unexpected backend errorBackendError. Decision is abstain, not a guess

The rule is uniform: when the router cannot prove the safe choice, it abstains and reports why. The harness prints calibration unlocked=False production_model=none on every run. The locked state is verified, not assumed.

06Privacy disclosure

  • No telemetry, no network, no background work. The package is Python stdlib only. The CLI runs once per invocation and exits.
  • The optional OpenRouter backend ships disabled by policy. DisabledByPolicy is raised if anything tries to use it while disabled. Even when an operator explicitly enables it, the transport carries hashes and labels only. No free text, no prompts, no file contents, no paths.
  • Receipts are hashes plus structured scores only. Closed fields, closed domains, append-only. The receipt writer refuses free text. No prompt text, user content, or session state is ever serialized into a receipt, log, or catalog metadata.
  • This repository contains only synthetic fixtures and demo JSON with placeholder IDs. No hosted prompt data, no real session transcripts, no user state.

Capability boundary: the plugin declares no tools, no hooks, no middleware, no settings (config_schema: {}). It does not hook the session loop, does not read the Hermes profile config, and writes nothing outside the receipts directory you explicitly pass. No Hermes core changes are required or made.
